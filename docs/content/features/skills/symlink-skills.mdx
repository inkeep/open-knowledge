---
title: Symlink skills
description: Point one AI tool's skills folder at another so both read the same skills.
---

Every AI tool reads skills from its own folder: `.claude/skills`, `.cursor/skills`, `.codex/skills`, and so on. OpenKnowledge keeps one real folder per skill and links the others to it, so a change reaches every tool without a second copy to keep in sync.

Link at whichever level matches what you want.

| Link this | Where | Use it when |
| --- | --- | --- |
| One skill | The skill's **Install** control in the dock | You want a particular skill in particular tools. |
| A whole folder | **Share skills between AI tools**, in Settings | You want two tools to share everything, now and later. |

## Link one skill

Open the skill's **Install** menu and check the tools that should read it, as in [Find and install skills](./find-and-install.mdx#choose-your-ai-tools). Each checked location points at the one real folder, so it cannot drift. Where the system does not allow symlinks, such as Windows without administrator rights or Developer Mode, a location gets a copy that refreshes from the source while unedited.

## Link a whole folder

The panel appears at both scopes: **Settings → User → Skills Studio** links your home folders, **Settings → This project → Skills Studio** the project-local ones.

<Image src="/images/skills-studio/settings-share-folders.png" alt="Share skills between AI tools lists each tool's folder with a Link button, showing Claude and Cursor already sharing one folder." width={1600} height={785} />

1. **Link** points one tool's folder at another. Both tools then see the same skills, including ones you add later.
2. **Add custom path** includes a folder OpenKnowledge has not detected, such as `~/.myteam/skills`.
3. **Unlink** turns a linked folder back into a real directory that keeps the skills it has today.

Linking refuses when the two folders hold different versions of the same skill. Resolve that first, then link.

## Writable linked layouts

Linked skill roots remain writable when the real folder stays inside the project for project skills, or inside the home directory for global skills. A link into private repository state, such as `.git`, is not a writable skill location.

Creating, importing, refreshing or renaming a skill refuses a root outside that boundary or a linked `SKILL.md` file.

Supporting-file writes, renames and deletions refuse the affected path when the file itself or a parent directory inside the skill folder is a link, even when its target is inside the project. Unrelated links do not block changes to other files. Refresh applies this check to every file it would write or remove, including `SKILL.md`. Replace a blocked link with a real file or directory before changing that path. Reading linked files remains supported.

For copies, relocating the source folder, and what OpenKnowledge writes where, see the [developer reference](./reference.mdx#file-layout).
